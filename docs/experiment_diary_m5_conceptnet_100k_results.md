## 1. Что проверялось

Цель M5 — проверить, существует ли на реальном семантическом графе ConceptNet диапазон масштабов, в котором граф можно заметно укрупнять, а его медленная коллективная динамика остаётся приблизительно той же.

Последовательность имеет вид:

`G0 -> G1 -> G2 -> ... -> G8`.

**Coarsening / укрупнение графа** — объединение нескольких исходных вершин в супервершины.

**Масштаб** — номер уровня этой последовательности. `G0` — исходный граф, `G1` — граф после первого укрупнения и т.д.

**Медленная мода** — коллективный паттерн состояния графа, который в выбранной диагностической динамике затухает медленнее быстрых паттернов.

**Медленное подпространство** — пространство нескольких выбранных медленных мод. Простыми словами, это набор основных крупномасштабных направлений поведения системы.

**Кандидат в параметр порядка** — амплитуда медленной моды. Мы используем слово «кандидат», потому что строгий принцип подчинения Хакена (`fast = h(slow)`) в M5 ещё не проверяется.

## 3. Как были выбраны 100 000 узлов

Первый вариант отбора — взять 100 000 наиболее высокостепенных узлов — оказался некорректным: 1 823 выбранных вершины после построения индуцированного подграфа потеряли всех выбранных соседей.

Поэтому использован исправленный детерминированный алгоритм:

1. найти крупнейшую компоненту полного отфильтрованного английского графа;
2. взять пул 300 000 наиболее высокостепенных кандидатов;
3. построить граф только внутри этого пула;
4. выбрать крупнейшую компоненту этого графа;
5. выполнить degree-prioritized connected traversal до ровно 100 000 узлов.

**Degree-prioritized connected traversal** — связный обход, при котором каждый следующий узел должен иметь связь с уже выбранной областью, а среди доступных кандидатов предпочтение получает узел с большей степенью.

## 5. Исправление масштабируемости перед финальным запуском

Первый 100k-run обнаружил скрытую операцию `O(N^2)`: для сравнения подпространств строились две плотные матрицы размера `N x N`.

При `N=100000` это потребовало бы около 74.5 GiB памяти.

Метрика была заменена математически эквивалентным вычислением через principal angles, использующим только матрицу порядка `r x r`, где в M5 `r <= 24`.

**Principal angles / главные углы** — углы между двумя подпространствами. Они измеряют, насколько повернулся один набор макродинамических направлений относительно другого.

После исправления полный regression suite перед M5 прошёл:

`79 passed, 6 skipped`.

## 6. Два заявленных режима сжатия

До просмотра результата были заданы:

- основной режим `target_reduction = 0.35`;
- стресс-режим `target_reduction = 0.50`.

**Target reduction** — желаемая доля вершин, которую алгоритм пытается убрать за один шаг.

Однако фактический `connectivity_matching` не смог достичь даже 35% на первом шаге и на всех шагах возвращал:

`shortfall_reason = insufficient_disjoint_adjacent_pairs`.

Это означает: алгоритм пытается объединять только соседние пары, причём вершину можно использовать в одном шаге только один раз. Доступных непересекающихся пар оказалось недостаточно для запрошенного объёма слияний.

Поэтому запросы 35% и 50% упёрлись в один и тот же фактический максимум и дали идентичную иерархию.

Следовательно, гипотезу «50% разрушает структуру сильнее 35%» этот запуск **не проверил**.

## 9. Cross-scale метрики

Для каждого перехода вычислялись три основных показателя.

### 9.1 Subspace distance

**Subspace distance** измеряет изменение самого медленного подпространства. Ноль означал бы практически одинаковые макродинамические направления.

Значения:

| Переход | Subspace distance |
|---|---:|
| 0 -> 1 | 1.4890 |
| 1 -> 2 | 1.1384 |
| 2 -> 3 | 1.8736 |
| 3 -> 4 | 1.2806 |
| 4 -> 5 | 1.7821 |
| 5 -> 6 | 2.0199 |
| 6 -> 7 | 2.0938 |
| 7 -> 8 | 1.3909 |

Preregistered threshold был `<= 0.45`.

Ни один переход его не прошёл.

Важное методологическое замечание: используемая projector-distance растёт с размерностью сравниваемого подпространства примерно до `sqrt(r)`. Поэтому один фиксированный абсолютный threshold 0.45, перенесённый с synthetic `r≈3` на real ConceptNet `r≈10–22`, становится значительно более строгим. Это требует отдельной нормализованной проверки в M5.1 и не должно исправляться задним числом внутри M5.

### 9.2 Slow eigenvalue error

**Eigenvalue error** — насколько изменились собственные значения медленных режимов между соседними масштабами. Собственное значение здесь связано со скоростью затухания режима.

Значения:

`0.0186, 0.0161, 0.0189, 0.0361, 0.0327, 0.0412, 0.0419, 0.0355`.

Все они значительно ниже preregistered threshold `0.30`.

Это интересный результат:

> скорости/временные масштабы спектральных режимов сохраняются намного лучше, чем сами направления соответствующих eigenspaces.

Иными словами, спектр по значениям довольно устойчив, но «какие комбинации понятий образуют медленные режимы» меняется сильнее.

### 9.3 Full trajectory error

**Trajectory error** — отличие динамики coarse graph от fine graph после разворачивания супервершин обратно на исходные вершины.

Значения:

`0.6081, 0.5581, 0.5990, 0.5280, 0.5156, 0.4690, 0.4086, 0.3925`.

Threshold M5 был `<= 0.50`.

Первые пять переходов его не проходят; последние три проходят.

Однако последние переходы уже имеют слишком малое фактическое сжатие и нестабильное `r`, а subspace distance остаётся большим.

Важно: это **full-state trajectory error**. M4.1 показал, что для Haken-редукции отдельно нужно считать slow-order-parameter trajectory error и post-transient error. Эти две M4.1-метрики пока не были включены в M5 plateau detector, поэтому M5 нельзя считать окончательной проверкой динамического сохранения именно параметров порядка.

## 10. Rank-r reconstruction error

Средняя ошибка восстановления полной траектории только из выбранных `r` slow modes на всех уровнях примерно равна 0.999.

Это означает, что выбранный маленький набор мод почти не восстанавливает **полное** микроскопическое состояние во всём временном интервале.

Это не равнозначно доказательству отсутствия низкоразмерной поздней макродинамики, потому что начальные возмущения содержат много быстрых компонент, а full-window metric учитывает их целиком.

Но данный результат является сильным предупреждением против слишком ранней интерпретации текущих slow modes как полноценного малого набора параметров порядка.

## 11. Plateau result

Preregistered критерии:

- минимум 2 последовательных qualifying transitions;
- `r_tolerance = 0`;
- `subspace distance <= 0.45`;
- `trajectory error <= 0.50`;
- `eigenvalue error <= 0.30`;
- фактическое уменьшение числа узлов >= 10%.

Результат:

**0 qualifying transitions**.

**0 plateau candidates**.

Причины отказа:

- `r_instability` — на всех переходах;
- `subspace_distortion` — на всех переходах;
- `trajectory_distortion` — на первых пяти переходах;
- `insufficient_reduction` — на последних четырёх переходах.

Eigenvalue gate не блокировал ни одного перехода.

## 12. Научная интерпретация M5

### Наблюдение

При текущем определении Haken-coarsening и заранее заданном detector на реальном ConceptNet-100k устойчивое semantic scale plateau **не обнаружено**.

### Что поддерживается данными

1. Граф можно последовательно сократить со 100 000 до 28 240 вершин pairwise connectivity matching без вычислительной аварии.
2. Спектральные значения медленных режимов меняются сравнительно мало.
3. Состав/геометрия медленного подпространства меняется намного сильнее.
4. Число выбранных slow modes не является стабильным по масштабам.
5. Full-state trajectory error уменьшается на поздних уровнях, но там почти прекращается само сжатие.

### Что данные пока не подтверждают

M5 не подтверждает гипотезу, что текущая реализация автоматически обнаруживает стабильный низкоразмерный Haken-like уровень организации ConceptNet.

### Что M5 не опровергает окончательно

M5 не опровергает более широкую Haken-гипотезу, потому что остаются три методических ограничения:

1. абсолютная subspace metric зависит от `r`, а threshold был перенесён с low-r synthetic режима;
2. detector использовал full trajectory error, а не M4.1 slow/post-transient metrics;
3. pairwise connectivity matching не способен реализовать заданный масштаб сжатия и поэтому не позволяет честно сравнить 35% и 50%.

## 13. Статус гипотез M5

### H1: существует preregistered plateau при умеренном coarsening

Статус: **не поддержана текущим M5**.

### H2: 50% coarsening разрушает структуру сильнее 35%

Статус: **не проверена**.

Причина: оба запроса дали одинаковый maximal pairwise matching из-за `insufficient_disjoint_adjacent_pairs`.

### H0: устойчивого plateau по текущим метрикам нет

Статус: **совместима с наблюдениями M5**.

Это не следует превращать в общий вывод «в ConceptNet нет Haken-like макроструктуры» до устранения перечисленных ограничений.

## 14. Следующий эксперимент: M5.1

M5.1 следует выполнять без переписывания M5 задним числом.

Необходимые изменения:

1. добавить dimension-normalized subspace metric, например `D_sub / sqrt(r_compared)`, сохранив исходную метрику рядом;
2. перенести из M4.1 в real hierarchy две динамические метрики: slow-order-parameter trajectory error и post-transient trajectory error;
3. заменить или дополнить pairwise connectivity matching методом, который действительно управляет target reduction: multi-node agglomeration, constrained clustering либо более сильный graph matching;
4. повторить 35% и 50% как реально различающиеся режимы;
5. только затем выполнять sensitivity analysis thresholds;
6. добавить matched-compression baselines, чтобы сравнить Haken-coarsening с обычным spectral/heavy-edge/random coarsening.

Главный новый исследовательский вопрос после M5:

> сохраняется ли на ConceptNet не полный eigenspace в абсолютной projector metric, а нормированная макродинамическая структура и динамика самих slow coordinates при управляемом уровне coarsening?

## 15. Итог одной строкой

**На реальном ConceptNet-100k текущий preregistered Haken plateau не обнаружен; при этом собственные значения slow modes устойчивы значительно сильнее их eigenspaces, а эксперимент выявил необходимость нормировать subspace metric по размерности и заменить pairwise matching на управляемое coarsening перед окончательной проверкой гипотезы.**
