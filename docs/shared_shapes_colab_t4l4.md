## Инструкция

1. В Colab выбрать Runtime → Change runtime type → T4 или L4 GPU.
2. Начать с PROFILE=10k, RUN_MODE=NEW. Для 100k выбрать High-RAM и новый RUN_ID.
3. Проверить INPUT_PATHS в конфигурационной ячейке; исходные TSV хранятся на Google Drive.
4. Выполнить Run all. Настройка CPU_BUDGET задаёт верхний лимит; реальное число ядер зависит от cgroup/affinity.
5. При обрыве запускать с теми же входом, SOURCE_REVISION и конфигурацией и RUN_MODE=RESUME.

### Исправление ошибки `NEW requires empty or absent run directory`

В раннем ноутбуке журнал `RUN_LOCAL/execution.log` создавался до запуска CLI и нарушал его проверку `NEW`. Исправлено: журнал сначала пишется на локальном SSD вне `RUN_LOCAL`, после появления `manifest.json` автоматически публикуется на Drive как `execution.log`. До создания manifest никакой фиктивный Drive-run не создаётся.

По умолчанию у исправленного ноутбука используется новый `RUN_ID` с суффиксом `-v2`, поэтому остатки неудачной попытки `-v1` остаются нетронутыми. Если вручную задан старый `RUN_ID` с непустым каталогом, выберите новый `RUN_ID` (не удаляйте контрольные точки). `RESUME` применим только к существующему запуску с корректным `manifest.json` и той же ревизией/параметрами.

## Параллельное выполнение

- nSBM — graph-tool на CPU/OpenMP с лимитами RAM на число рестартов.
- Ego extraction — CPU-потоки; следующая пачка извлекается одновременно с VF2 текущей.
- VF2 — CPU spawn процессы, ограниченный одной ожидающей пачкой конвейер.
- CuPy GPU — степени, W-проекция и Wishart-kNN, если Wishart включён.
- Хаффман, общий реестр форм, точный архив и декодер — CPU.

## Прогресс и измерения

Строки PROGRESS в ноутбуке показывают общий процент относительно количества запланированных фаз, номер шага и реальную долю выполненной текущей фазы. В длительных фазах: число завершённых рестартов nSBM, обследованных центров VF2, проверенных групп форм. Текущий срез — progress.json на Drive.

report.json содержит phase_timing_seconds для эксперимента, методов и уровней coarsening; scan.meta — extraction_seconds, vf2_seconds, scan_wall_seconds, считанные/переиспользованные shards, фактический CPU split. extraction и VF2 могут перекрываться: их суммарное время не обязано совпадать с wall time.

## Точность и RESUME

Локальный SSD — место вычислений. Только подтверждённые архивы уровня с SHA метаданными публикуются на Drive. Файлы копируются во временный путь, SHA проверяется, затем выполняется переименование. Метка COMPLETED публикуется последней, после проверки метода и итогового архива. Временные ZIP перехода и неподтверждённые levels не копируются.

Старые checkpoints формата v1 нельзя продолжать новым shared-shapes v2. Менять научную настройку ISOMORPHISM_LEVEL в RESUME нельзя. Исходный граф восстанавливается точно со всеми направленными типизированными рёбрами, ID и binary64 весами.

CI smoke подтверждает синтаксис ноутбука и CPU-функциональность, но не реальное выполнение T4/L4, RAM-пик и выигрыш производительности на ConceptNet-100k. Эти результаты должны измеряться отдельным полным Colab-запуском.
