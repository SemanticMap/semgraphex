# Общие идентификаторы графовых форм

## Решение и границы

Ввести один реестр точных символов на всю компрессионную иерархию. Настраиваемое
сравнение форм оставить проекцией этого реестра, а не изменяемым контрактом декодера.
Реализация относится к nSBM-пайплайну `hypothesis/recursive_codec.py`; старый Wishart-
оркестратор и статистическое обучение nSBM не переписываются.

Основание: ревизия `7288168c6cdd4c6d1113499599e7472768e04657` создавала локальные
формы в `grammar_codec._canonicalize_shapes`, а `contract_records` и `_state`
независимо строили типы `L{level}_S{local}`. Поэтому одинаковые правила на разных
переходах имели разные символические имена. Переноса одного `GraphDictionary`
за цикл недостаточно: окончательные формы заново определяются точным кодеком.

## Идентичность

Внутри реестра `symbol_id` — неизменяемый целочисленный индекс. Внешняя ссылка —
`(dictionary_namespace, symbol_id)`. Номер уровня, nSBM-блок, частота, исходные URI,
порядок обхода узлов и битовое слово Хаффмана не входят в определение формы.

Точная форма содержит ориентированный внутренний мультиграф, имена отношений,
петли, кратности каждого отношения и глобальные дочерние символы в позициях узлов.
Обычный узел имеет тип `ATOM`, ранее созданный символ — `S:<id>`.
Вес, исходный идентификатор ребра, внешние привязки и исходные вершины остаются
точными данными вхождения в существующих потоках кодека.

Следствия:

- одинаковое правило на уровнях 0 и 4 получает один ID;
- разные веса не создают новую внутреннюю форму, но сохраняются побитово;
- разные внешние связи используют один core и отдельные существующие ports;
- одинаковая топология с разными дочерними символами — разные точные правила;
- дочерние ссылки разрешены только на уже зарегистрированные символы: циклов нет.

Это идентичность рекурсивной правой части правила. Эквивалентность полностью
развёрнутых графов при разных способах разбиения НЕ обещается. Для неё потребовалась
бы отдельная ограниченная процедура раскрытия с учётом портов; она не добавляется
спекулятивно.

## Настраиваемый уровень изоморфизма

| `level` | Сохраняется при сравнении |
|---|---|
| `topology` | Неориентированная топология, число узлов, петли и кратность |
| `directed` | То же, плюс направление |
| `typed` | То же, плюс имена отношений и их кратности |
| `recursive` | То же, плюс идентичности дочерних символов |

Каждый режим проверяет точный изоморфизм соответствующей проекции. Это не
«процент изоморфизма» и не порог edit distance. Отношение близости по порогу может
быть нетранзитивным и потому не должно молча становиться идентичностью символа.

`ShapeRegistry.classes(level)` возвращает классы похожести, не изменяя `symbol_id`.
`run_recursive(..., isomorphism_level="typed")` сохраняет выбранную оценку в отчёте.
Сравнение уже сохранённого словаря доступно без повторного обучения/сжатия:

```bash
python -m semmap_haken.shape_identity runs/recursive/level_002.zip --level typed
```

Существующий верхнеуровневый Colab launcher использует default `recursive`.
Новый CLI выше предназначен для сравнения; он не переключает lossless-контракт.

## Почему не hash(canonical_graph)

WL и дешёвые структурные сигнатуры не являются доказательством изоморфизма.
Поэтому ID выделяется реестром после точной VF2-проверки; сигнатура используется
только как индекс кандидатов. Для параллельных связей сравниваются мультимножества
меток (`Counter`), а не множества (`set`). Новых зависимостей нет: используется
уже имеющийся NetworkX.

Независимые новые реестры могут назначить одинаковым формам разные номера.
Стабильность между запусками обеспечивается загрузкой того же реестра, а не
обещанием универсального content hash. Изменение порядка регистрации не меняет
уже выданные ID, но может изменить номера впервые найденных форм.

## Хранение и восстановление

Новый envelope: `semmap_nsbm_exact_hierarchy_v2`.

```text
dictionary.json                      # все точные определения один раз
final_graph.zip                      # существующий компактный exact baseline
source_ids.json
transition_000_001/
    manifest.json
    shape_refs.json                  # local alias -> global ID + permutation
    variants.json
    occurrences.bin
    symbols.huff
    internal.bin
    ports.bin
```

Локальные алиасы остаются в потоках Хаффмана: это транспортные номера, не новые
семантические символы. Код Хаффмана зависит от частот конкретного потока и не
должен быть постоянным идентификатором формы.

`ShapeRegistry.references` сопоставляет локальную форму глобальной и сохраняет
перестановку вершин. `expand` точно восстанавливает локальный порядок узлов,
relation IDs и edge slots перед вызовом существующего обратного декодера.
Потоки весов, внутренних рёбер и портов не переписываются. `rules.json` не нужен
в новом envelope: он выводится из shape/node_types и не читается reverse decoder.

Обратное чтение v1 сохранено. Новая рекурсивная сборка пишет v2; продолжение v1
через RESUME явно отклоняется — нужен отдельный NEW run. Старые архивы не
перекодируются и не удаляются. Не следует запускать NEW поверх старой папки.

## Публикация, параллелизм и проверка

Реестр изменяет только основной процесс после отбора фигур. Воркеры по-прежнему
ищут кандидатов; они не выделяют глобальные ID. Порядок принятия остаётся
детерминированным при фиксированном потоке кандидатов.

Реестр, ссылки и финальный граф записываются в один временный ZIP, затем атомарно
переименовываются. Принятие уровня требует полного обратного восстановления и
уменьшения размера всего ZIP. Метаданные checkpoint публикуются после проверки.
Неудачная попытка не меняет предыдущий архив; итоговый отчёт перечитывает принятый
снимок. Идентичность scan checkpoint включает hash реестра и версию контракта.

Не изменены: bounded CPU scan, CUDA-этапы, nSBM partitions, портовые payload,
non-overlap selection, исходные IDs, binary64 и проверка SHA архивов.

## Что упрощено

- Один `_next_types` вместо двух независимых правил именования.
- `_state` читает нужные потоки прямо из ZIP вместо создания вложенного временного ZIP.
- `contextlib.nullcontext` вместо собственного `_NoZip`.
- В v2 нет повторных `shapes.json` и выводимых `rules.json` на каждом переходе.
- Нет фабрик, стратегий-плагинов, базы данных, отдельного сервиса или нового entropy codec.

Candidate `GraphDictionary` остаётся локальной структурой discovery. Это не второй
источник истинных symbol IDs: authoritative identity теперь у реестра exact codec.
Полное объединение discovery/codec было бы более рискованной, не нужной здесь
перестройкой: discovery работает с CSR, exact codec — с исходными multiedge records.

## Проверки и ограничения

Проверки: переименование вершин; смена локальных relation IDs; повтор формы на
другом масштабе; разные дочерние символы; петли; мультимножества параллельных типов;
коллизия фильтра; восстановление перестановок; сериализация/RESUME; неизвестные
и прямые циклические ссылки; три обратных перехода с битовым сохранением весов;
одна запись формы в архиве; чтение старого v1 существующими тестами.

Существующий локальный предварительный отбор по размеру standalone-архива пока
консервативен: он ещё не кредитует уже оплаченные глобальные формы. Итоговый
контроль размера полного shared-архива точен. Увеличение сжатия на ConceptNet,
ускорение и выигрыш RAM не заявляются до реального эксперимента.

Использованные скиллы: `design-minimal-architecture`, `simplify-code-structure`,
`grammar-based-graph-compression`, `rlm-roec-context-reasoning` из
`stanta/skills_superset`. Область изменения намеренно ограничена identity и
recursive envelope; unrelated cleanup не включён.
